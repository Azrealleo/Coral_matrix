# 双累加器、输入复用：独立候选（尚未RTL验证）

当前是工具/测试包v2：修正虚拟机编译器将mt4选择值生成为`16 << 25`时，
v1审计只查找固定`lui a0,0x20000`造成的误报。不删除检查，改为基本块内标量
常量传播，仍拒绝错误移位、未知来源及跨控制流拼接的假常量。
这只是常量生成检查，不证明动态tile/行选择正确，RTL探针仍是必需门槛。
v1/v2全部C++及头文件逐字节一致，算术、布局、指令、计数器均未修改。
使用独立`llm_vme_pair_v2` Bazel包和工具目录，避免覆盖失败v1源码清单及日志。

固定官方8e4df09b、单NPU ITCM256KiB/DTCM512KiB；不升级RTL/ISA，
不改Depthwise，不覆盖正在执行或已验收的mature/large/sweep实验。

## 实际改动

N每两个完整的16通道块使用mt0与mt4两个INT32累加器组。
同一Tk4中输入B只加载一次，分别与两组权重相乘；A0/B/A1使用
v8/16/24为基址、每行相隔两个向量寄存器，最高v30。
两条矩阵指令在同一K循环里累加，完成后分别读回。
单组Tk4的向量加载指令从单tile两次共16条减少到12条，即减少25%；
这不是端到端提速预测，也不是外部AXI/DRAM流量减少25%。

N不足完整32通道时，尾部最多两个块继续使用已验证的configure-once单tile。
每次初始化两个累加器，TSS读写索引分别选择tile0/tile4；不把tile1误当独立INT32组。
保持原X+128补偿、预打包格式、M/K/N尾部清零和直接跨步输出。
范围仍M1..16、K1..64、N1..64，raw INT8到INT32，不含量化/激活或模型。
性能及RTL探针W[-127,127]、X[-128,127]；native额外极值不是硬件承诺。

同ELF五路径：官方RVV、**上一版configure-once单tile VME完整/复用**、
双tile候选完整/复用。不是和最早慢版本比较，不能拼接旧ELF周期。
复用路径同时报告排除预打包的边际周期和计入一次预打包的首用/四次摊销。
准备过程只从固定个人提交6ee7fd6读取父资源，即使以后父目录更改也不替换基线。

## 新的验证门槛

- 新13组指令探针包含单tile、双tile、两次双tile、M部分宽度、N33/47/48/63尾部和不同权重，
  不能用旧mature探针替代。
- 真实RV32静态审计要求全宽/部分宽度两个PairKLoop、mt0/mt4不同目的、
  v8/v24不同权重基址、B的v16/18/20/22恰好加载一次，循环内无存储/调用/VSET。
- 新增pair_groups/single_groups软件计数，性能与探针均从前门读回逐项验收；
  只跑单tile而冒充双tile会被拒绝。计数不是独立硬件退休证明。
- 原始日志/XML/退出状态、无fault/自然halt、数值/签名/guards和前门读回门槛保留。
  栈仍只检查底部64字节，不是完整栈水位。
